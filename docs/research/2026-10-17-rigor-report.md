# NAILA: deeper, not bigger

**Answer (1): build a measured, causally correct conversational loop before changing the model roster.** My engineering recommendation is to prioritize session isolation, genuine end-to-end interruption, correct clocks, inference scheduling, and evidence-based turn-taking. These priorities follow from concrete implementation gaps below and the interaction dimensions in [Full-Duplex-Bench](https://arxiv.org/html/2503.04721v2).

**Answer (2): start from synchronized microphone, speaker-reference, playback, image and transport recordings with independent annotations—not only transcripts, generated scene descriptions, or advertised model latency.** The distinction matters because current visual context is reduced to description/counts, and current timing copies an RTP timestamp into a field named milliseconds. [ai-server/agents/response_generator.py:184](/Users/j/code/robo-naila/ai-server/agents/response_generator.py:184), [hub/src/webrtc.rs:247](/Users/j/code/robo-naila/hub/src/webrtc.rs:247), [hub/src/grpc.rs:286](/Users/j/code/robo-naila/hub/src/grpc.rs:286).

**Answer (3): use replayable hardware-in-the-loop experiments, causal endpointing evaluation, structured cancellation, model/quantization ablations, and distributed traces. Answer (4): let held-out public benchmarks, independently labeled local recordings, standard listening tests, and explicit protocol invariants arbitrate.** The relevant external foundations are [eot-bench](https://github.com/livekit/eot-bench), [AEC Challenge](https://github.com/microsoft/AEC-Challenge), [Open ASR Leaderboard](https://github.com/huggingface/open_asr_leaderboard), [ITU-T P.808](https://www.itu.int/ITU-T/recommendations/rec.aspx?id=14665), and [RFC 7587](https://www.rfc-editor.org/rfc/rfc7587).

## (1) What I judge a top professional would do here

### A. Make the claimed system observable and the measurement causal

**Repo facts.** README advertises sub-700 ms response latency; the streaming document budgets 400–700 ms with “streaming Whisper.” The implemented RPC buffers an utterance, creates processing after `END`, and then transcribes its WAV. The default hub waits 15 × 20 ms of silence before `END`. [README.md:42](/Users/j/code/robo-naila/README.md:42), [docs/STREAMING_ARCHITECTURE.md:166](/Users/j/code/robo-naila/docs/STREAMING_ARCHITECTURE.md:166), [ai-server/rpc/service.py:299](/Users/j/code/robo-naila/ai-server/rpc/service.py:299), [ai-server/rpc/service.py:451](/Users/j/code/robo-naila/ai-server/rpc/service.py:451), [hub/src/vad.rs:18](/Users/j/code/robo-naila/hub/src/vad.rs:18).

**Inference.** This is streaming transport with utterance-level STT, not demonstrated incremental ASR. The documented budget does not explicitly account for the 300 ms endpointing wait. I cannot establish actual latency without recordings. Existing orchestration timing uses fast mocks and text input; the hub loopback uses an echo server and mock transport. Neither establishes the acoustic response claim. [ai-server/tests/performance/test_performance.py:180](/Users/j/code/robo-naila/ai-server/tests/performance/test_performance.py:180), [hub/tests/loopback.rs:23](/Users/j/code/robo-naila/hub/tests/loopback.rs:23).

**Recommendation.** Define the primary latency as physical end of user speech → first audible, relevant response speech. Also report endpoint decision, STT completion, LLM first token, first usable phrase, TTS first sample, transport delivery and actual playout. Count failures and timeouts rather than excluding them. Separate cold/warm and concurrent conditions; use a same-device recording clock for the acoustic endpoints and traces for attribution. OpenTelemetry supplies timestamped span events, but cross-host clock error still needs measurement. [OpenTelemetry trace API](https://opentelemetry.io/docs/specs/otel/trace/api/).

### B. Fix stream ownership and clock contracts before optimizing models

**Repo facts.** The hub opens one streaming RPC and tags inputs by device/conversation. The Python stream owns one `audio_buffer`, `processing_task` and target output rate; each input overwrites device/conversation variables, and `START` clears the buffer. [hub/src/grpc.rs:216](/Users/j/code/robo-naila/hub/src/grpc.rs:216), [hub/src/grpc.rs:286](/Users/j/code/robo-naila/hub/src/grpc.rs:286), [ai-server/rpc/service.py:212](/Users/j/code/robo-naila/ai-server/rpc/service.py:212), [ai-server/rpc/service.py:234](/Users/j/code/robo-naila/ai-server/rpc/service.py:234).

**Inference.** Interleaved devices can overwrite or combine utterance state and cancel each other's work. This follows from the shared state; I did not reproduce an incident. A professional response can be either explicit single-device admission now or state ownership per `(device, session)`; shipping multi-room functionality is not necessary to establish the invariant.

**Repo fact and external rule.** RTP timestamps are copied through `AudioFrame.timestamp` to `AudioInput.timestamp_ms`, without conversion in that path. Opus RTP uses a 48 kHz clock, independent of sample-rate mode. [hub/src/webrtc.rs:247](/Users/j/code/robo-naila/hub/src/webrtc.rs:247), [hub/src/grpc.rs:296](/Users/j/code/robo-naila/hub/src/grpc.rs:296), [RFC 7587 §6.1](https://www.rfc-editor.org/rfc/rfc7587).

**Recommendation.** Specify clock domain, units, wraparound and origin; distinguish media sample position from capture time. Make reconnect/session epochs and response-generation identity survive routing, so delayed frames cannot reach a replacement session. Currently output routing looks up `device_id`, and `TtsFrame` carries no conversation/generation identity. That creates a stale-delivery risk, not a verified observed leak. [hub/src/grpc.rs:372](/Users/j/code/robo-naila/hub/src/grpc.rs:372), [hub/src/audio.rs:57](/Users/j/code/robo-naila/hub/src/audio.rs:57).

### C. Treat interruption as a transaction extending to the loudspeaker

**Repo facts.** Proto/server support `INTERRUPT`, but the hub's internal event enum and mapping have only Start/Continue/End. A valid new `END` cancels the old task; `START` does not. The interrupt branch cancels processing and clears the input buffer, without draining the stream's output queue there. [proto/naila.proto:90](/Users/j/code/robo-naila/proto/naila.proto:90), [hub/src/audio.rs:35](/Users/j/code/robo-naila/hub/src/audio.rs:35), [hub/src/grpc.rs:270](/Users/j/code/robo-naila/hub/src/grpc.rs:270), [ai-server/rpc/service.py:243](/Users/j/code/robo-naila/ai-server/rpc/service.py:243), [ai-server/rpc/service.py:322](/Users/j/code/robo-naila/ai-server/rpc/service.py:322).

**Recommendation.** Specify a turn state machine and response epoch, propagate cancellation through inference, discard obsolete queued audio, flush playback for an accepted interruption, and record what actually played. Verify cancellation of native/threaded work rather than assuming Python task cancellation stops it: gRPC explicitly assigns cessation of application computation to the application. [gRPC cancellation guide](https://grpc.io/docs/guides/cancellation/).

**Repo fact and inference.** The client speaker queue permits 500 frames; at the documented 20 ms framing that is nominal capacity for 10 seconds, not evidence it normally fills. Queue capacity alone cannot guarantee a fast stop. [devices/audio-client/audio_client/audio.py:19](/Users/j/code/robo-naila/devices/audio-client/audio_client/audio.py:19), [devices/audio-client/README.md:9](/Users/j/code/robo-naila/devices/audio-client/README.md:9). Proposed invariant: once cancellation is acknowledged, no audio from that response epoch is accepted for playback, with residual hardware-buffer latency explicitly measured.

**Recommendation.** Connect memory to delivery semantics. The orchestrator commits response text after graph completion, without a playout acknowledgment in that method. Define whether interrupted or unheard text is remembered and test restart behavior; do not silently equate generated text with what the user heard. [ai-server/agents/orchestrator.py:106](/Users/j/code/robo-naila/ai-server/agents/orchestrator.py:106).

### D. Investigate avoidable scheduling delay before a model replacement

**Repo facts.** STT calls `model.transcribe` in an executor, returns its segments, then iterates them synchronously in `_process_segments` from the async caller. The library says actual transcription starts during iteration. Warmup similarly calls `transcribe` without consuming its result. [ai-server/services/stt.py:255](/Users/j/code/robo-naila/ai-server/services/stt.py:255), [ai-server/services/stt.py:393](/Users/j/code/robo-naila/ai-server/services/stt.py:393), [ai-server/services/stt.py:424](/Users/j/code/robo-naila/ai-server/services/stt.py:424), [ai-server/services/stt.py:171](/Users/j/code/robo-naila/ai-server/services/stt.py:171), [faster-whisper usage warning](https://github.com/SYSTRAN/faster-whisper#usage).

**Inference / recommendation.** Much of inference likely executes on the event-loop thread, and warmup may not perform the intended decode. Profile loop stalls, consume the generator within the worker boundary, then compare cold/warm distributions. This needs verification against the installed version; it is a strong source-backed hypothesis, not a measured stall duration.

**Repo fact / recommendation.** First-sentence synthesis waits for the next sentence or stream completion because of `pending_sentence` lookahead. Measure that wait explicitly and consider a separate completion control message so the first phrase can be delivered promptly. Preserve continuity and finalization correctness when comparing alternatives. [ai-server/agents/response_generator.py:222](/Users/j/code/robo-naila/ai-server/agents/response_generator.py:222), [ai-server/agents/response_generator.py:250](/Users/j/code/robo-naila/ai-server/agents/response_generator.py:250). Unmute's own load-testing and device-placement discussion supports investigating scheduling/contention as well as model throughput. [Unmute](https://github.com/kyutai-labs/unmute).

### E. Tune the acoustic and turn-taking operating point from evidence

**Repo facts.** Default VAD is `VeryAggressive` with 300 ms hangover, while documentation says Quality mode. The server drops buffered utterances shorter than 450 ms. Speex AEC uses a fixed 100 ms tail and silently passes through microphone data when unavailable; the callback increments `aec_frames_processed` even in that fallback. [hub/src/vad.rs:18](/Users/j/code/robo-naila/hub/src/vad.rs:18), [docs/STREAMING_ARCHITECTURE.md:134](/Users/j/code/robo-naila/docs/STREAMING_ARCHITECTURE.md:134), [ai-server/rpc/service.py:42](/Users/j/code/robo-naila/ai-server/rpc/service.py:42), [devices/audio-client/audio_client/aec.py:9](/Users/j/code/robo-naila/devices/audio-client/audio_client/aec.py:9), [devices/audio-client/audio_client/audio.py:89](/Users/j/code/robo-naila/devices/audio-client/audio_client/audio.py:89).

**Recommendation.** Sweep VAD aggressiveness, hangover, short-clip threshold and AEC configuration jointly. Include short “yes/no/stop,” hesitations, soft speech, assistant-only playback, double talk, changed speaker volume and different mic distances. Make AEC availability an explicit measured state. Select an endpointing latency/false-cutoff frontier; do not declare a lower timeout an improvement by itself. [eot-bench methodology](https://github.com/livekit/eot-bench), [AEC Challenge](https://github.com/microsoft/AEC-Challenge).

### F. Preserve evidence and uncertainty at the vision boundary

**Repo facts.** Scene description is generated from detected class counts; visual LLM context contains description/counts, not pixels. Scene confidence is the average confidence of detections. The cache is keyed by image bytes although `analyze_scene` accepts a query. [ai-server/services/vision.py:458](/Users/j/code/robo-naila/ai-server/services/vision.py:458), [ai-server/services/vision.py:481](/Users/j/code/robo-naila/ai-server/services/vision.py:481), [ai-server/services/vision.py:506](/Users/j/code/robo-naila/ai-server/services/vision.py:506), [ai-server/agents/response_generator.py:184](/Users/j/code/robo-naila/ai-server/agents/response_generator.py:184).

**Inference / recommendation.** Class/count summaries cannot substantiate arbitrary claims about color, text, relations or current scene freshness. Keep frame identity, capture time, boxes, class scores and transformation provenance available; explicitly mark unsupported questions. Separate “detected” from “known absent.” Test detector accuracy using COCO's AP/recall definitions and local labeled scenes; measure final-answer grounding separately. [COCO evaluator definitions](https://github.com/cocodataset/cocodataset.github.io/blob/master/dataset/detection-eval.htm). Qwen's temporal alignment is an architectural reference for preserving when evidence occurred, not a reason to add its model. [Qwen2.5-Omni §2](https://arxiv.org/html/2503.20215v1).

**Recommendation.** Avoid presenting STT or scene scores as calibrated probabilities: the repo exponentiates mean segment log probability for STT and averages detector scores for scenes. ## (3) Specific methods and tools

The following is an implementation proposal, not work performed in this research turn.

1. **A versioned replay harness with three entry points:** microphone/acoustic loop, WebRTC full stack, and direct gRPC for isolating inference. Extend the role of the existing recorded-audio RPC helper and hub mock loopback; retain both deterministic transport checks and real-model trials. Store per-case input hashes, annotations, model hashes, settings, timestamped outputs and failures. [ai-server/README.md:166](/Users/j/code/robo-naila/ai-server/README.md:166), [hub/tests/loopback.rs:110](/Users/j/code/robo-naila/hub/tests/loopback.rs:110).
2. **OpenTelemetry spans/events plus local audio recording:** correlate by session and turn; instrument queue age, ASR iteration, first phrase, synthesis, output and playout. Use Python sampling/event-loop profiling to test the lazy-inference hypothesis; use OS CPU/memory/thermal counters during the target-device replay. Trace semantics come from [OpenTelemetry](https://opentelemetry.io/docs/specs/otel/trace/api/); the suspected execution boundary is [stt.py:393](/Users/j/code/robo-naila/ai-server/services/stt.py:393).
3. **State-machine and fault-injection testing:** generate interleaved A/B utterances, reconnect with the same device ID, delay old outputs, interrupt during every stage, fill queues, disconnect gRPC and stall playback. Assert ownership, bounded queue residence, deterministic terminal state and no obsolete playback. Build on existing Tokio cancellation/timeout mechanics and Python stream tasks rather than introducing a new orchestration framework. [hub/src/device.rs:104](/Users/j/code/robo-naila/hub/src/device.rs:104), [hub/src/grpc.rs:391](/Users/j/code/robo-naila/hub/src/grpc.rs:391), [ai-server/rpc/service.py:229](/Users/j/code/robo-naila/ai-server/rpc/service.py:229).
4. **Paired ablations:** baseline versus one change at a time—consume ASR inside worker; remove first-sentence lookahead; endpointing threshold; AEC available/unavailable; STT VAD on/off; quantization/thread/offload/context depth. Reuse identical held-out inputs, randomized condition order and repeated trials; report paired confidence intervals and failure rates. Use `llama-bench` for prompt/decode/context experiments, then full application replay; use the Open ASR normalizer/scorer for WER and RTFx. [llama-bench](https://github.com/ggml-org/llama.cpp/blob/master/tools/llama-bench/README.md), [Open ASR local evaluation](https://github.com/huggingface/open_asr_leaderboard).
5. **Causal endpoint/overlap adapters:** integrate NAILA with pinned eot-bench/FDB versions. Feed only information available at each real-time decision; never provide future transcripts. Compare current silence timing before trialing a learned endpoint model. If testing incremental Whisper, implement and measure a commitment policy; streaming its final transcript is insufficient. [eot-bench](https://github.com/livekit/eot-bench), [Whisper-Streaming](https://arxiv.org/abs/2307.14743).
6. **Independent labels and listening panels:** use fixed label instructions, adjudicate disagreements and retain disagreements. For listening quality use a P.808-style protocol; for conversational preference run a separate blinded, randomized paired study with target users. Standardized speech-quality listening does not establish whether a companion's personality is desirable. [ITU-T P.808](https://www.itu.int/ITU-T/recommendations/rec.aspx?id=14665).

| **AEC Challenge test sets + ITU-T P.808 listening protocol** | Replay aligned microphone/far-end reference signals through the actual AEC implementation; test single and double talk, score speech preservation and echo suppression with the challenge's assessment tools where available, then validate on actual hardware/rooms. [RFC 7587](https://www.rfc-editor.org/rfc/rfc7587), [gRPC cancellation](https://grpc.io/docs/guides/cancellation/). | Custom invariants are objective once specified, but are not external certification; operator chooses service budgets. |

[FDB](https://arxiv.org/html/2503.04721v2), [ITU](https://www.itu.int/ITU-T/recommendations/rec.aspx?id=14665). | Preference is independent evidence, not universal objective truth. **Proposed acceptance rule:** reject a speed change that improves latency by dropping valid short requests, increasing false cutoffs, degrading grounded answers or violating session isolation. Require improvement on the selected held-out operating point and no material regression on declared quality constraints. This is my recommended decision rule, not a requirement imposed by a benchmark. The need to preserve timing and content separately follows from [FDB v1.5](https://arxiv.org/html/2507.23159v1) and [VoiceBench](https://arxiv.org/html/2410.17196v3).

## Recommended order and bounded scope

My proposed first engineering cycle is: **capture a reproducible baseline → address stream/clock correctness and verify ASR scheduling → establish actual stop-to-speaker cancellation → remove measured phrase delay → tune acoustic/endpointing tradeoffs → validate existing vision claims.** Each step is tied to a cited finding above. Retain the existing cascade unless controlled results show that its architecture, rather than an implementation defect, prevents the chosen interaction target. Kyutai's Unmute demonstrates a serious cascade reference; Moshi provides a distinct alternative with different tradeoffs.
